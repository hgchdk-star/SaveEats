## T-2026-11-05-01 한 주문의 오프라인 완료 확인 저장 실패 → 앱 재시작 → 완료 복구 — 통과

- 환경: iPhone, 실제 Supabase 연결(`EXPO_PUBLIC_DATA_SOURCE=supabase`), 테스트용 계정.
- 실패 재현 방법: 비행기 모드(**실제 네트워크 단절**). 개발용 실패 주입은 쓰지 않았다.
- 테스트 주문: 동대문엽기떡볶이 로제메뉴 16,000원.

| 단계 | 결과 |
|---|---|
| 새 주문 | 직접 주문 이어가기 화면에 은행명·계좌 끝 4자리·금액이 표시됨 (GAP-01 확인) |
| `아직이에요` → 내역 → `주문 이어하기` | 같은 주문의 직접 이어가기 화면으로 돌아옴 |
| 비행기 모드 후 `주문 완료했어요` | `완료 확인을 저장하지 못했어요`, `송금을 이미 완료했다면 다시 송금하지 마세요.`, `상태 저장 다시 시도` 표시 |
| 재시도 버튼을 누르지 않고 앱 완전 종료 → 인터넷 연결 → 앱 열기 | 기존 주문이 `주문 완료`로 복구됨 |
| 부수 확인 | 같은 주문이 추가로 생성되지 않았고 토스도 자동으로 열리지 않음 |

판정: **통과 — 한 주문에 한정.**

## T-2026-11-05-02 두 주문(A·B)의 완료 확인 대기를 동시에 남기고 앱 재시작으로 복구 — 통과 (개발용 실패 주입)

- 환경: iPhone, 실제 Supabase 연결, 테스트용 계정. 개발 서버를 `EXPO_PUBLIC_DEV_CONFIRM_FAILURES=2`로 시작.
- 실패 재현 방법: **개발용 실패 주입.** 네트워크는 끊지 않았다. 앞의 완료 확인 2번을 서버로 보내기 전에 실패시킨 것이고, 실제 서버 오류나 서버에는 적용됐는데 응답만 잃은 경우가 아니다.
- 순서: A 주문 → `주문 완료했어요`(실패) → B 주문 → `주문 완료했어요`(실패) → 내역에서 두 주문의 대기 확인 → 앱 완전 종료 → 재실행.
- 결과: 테스터(서정) 보고 "통과". 단계별 화면 상세(토스트 문구, 각 행의 표시)는 기록되지 않았다.
- 판정: **통과 — 개발용 실패 주입으로 만든 A·B 동시 대기의 앱 재시작 복구에 한정.**

## 이 기록이 확인하지 않은 것 (확대 금지)

- 실제 네트워크 단절로 두 주문의 대기를 남기고 복구하는 경우 (T-02는 개발용 실패 주입)
- 한 주문의 복구·삭제가 다른 주문에 영향을 주지 않는지 (A만 재시도해 B가 그대로인지 — 아직 안 함)
- 실제 토스 사전입력·실행 차단, 원격 ON→OFF
- 취소 화면 도달. 이 테스트에서는 도달할 경로가 없어 진행하지 못했다 (`toss-integration-device-checklist.md`의 알려진 문제 1)
- 앱 종료 시점 이후의 다른 상황(앱 종료 후 로그아웃, 다른 계정 등)
- Android, 다른 은행·기기·OS
