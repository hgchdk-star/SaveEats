# SaveEats 토스 딥링크 — 사용자 실기기 테스트 결과

기록일: 2026-10-14 (Asia/Seoul).

## 확인한 결과

| 환경 | 테스트 경로 | 사용자 보고 | 판정 |
|---|---|---|---|
| iPhone / Expo Go | 인터넷 터널 QR → 본인 은행/계좌 입력 → 토스 화면 열기 | 안내한 사전입력 확인 절차에 대해 “그것도 했어@ 잘 돼!!”, 이후 “오케이 잘 돼!” | 사용자 보고 기준 진입·사전입력 성공 |
| Android / Expo Go | 동일 테스트 앱 | “오 안드로이드도 됨!! 잘됨!!” | 사용자 보고 기준 진입·사전입력 성공 |

테스트 앱 코드의 후보는 `supertoss://send?amount=1&bank={인코딩한은행명}&accountNo={본인계좌번호}&origin=qr`다. 본인 계좌 입력값은 수집하지 않았다. 설치된 Expo SDK는 57.0.28, React Native는 0.86.3이다. 기기 모델, OS/토스/Expo Go 버전, 실제 입력 은행명은 아직 기록되지 않았다. 동일한 금융앱/OS의 다른 버전과 모든 은행에 일반화하지 않는다.

이 판정의 근거는 대화에서 사용자가 보고한 결과다. 각 필드의 화면 캡처나 독립적인 시스템 검증 자료는 수집하지 않았다. 실제 송금을 하지 않고 앱 진입·사전입력까지만 확인하도록 안내한 테스트이며, 송금 성공을 검증한 결과가 아니다.

## 범위의 경계

- Expo Go 실험은 `canOpenURL` 설치 조회를 생략하고 `openURL`을 직접 시도했다. iOS/Android 네이티브 조회 설정이나 미설치 판정은 이번 사용자 테스트로 통과 처리하지 않는다.
- 로컬 PENDING 저장 및 호출 예약, 개별 복사 fallback, 모의 flag는 코드에 있다. 두 기기에서 이 모든 오류 경계를 사용자가 직접 시험했다고 간주하지 않는다.
- 원격 Kill Switch, 생산 서버 주문 저장, USER_CONFIRMED 저장 복구, 독립 SaveEats development/release build는 별도 검증이 필요하다.
- 이번 사용자 확인은 비공식 후보의 동작 근거를 보강하지만 공식 지원 계약이나 송금 VERIFIED 상태를 의미하지 않는다.

## 유지할 정책

비공식 토스 딥링크 우선 시도, 실기기 검증 환경만 활성화, 실패 시 계좌번호/금액 개별 복사, `tossDeepLinkEnabled` 원격 Kill Switch, `PENDING → USER_CONFIRMED`, 중복송금 방지를 그대로 유지한다.

다음 통합 단계는 실제 SaveEats 앱에서 같은 후보를 적용하고 플랫폼별 네이티브 조회 설정 및 실패 경로를 검증하는 것이다. 기기/OS/토스 버전과 은행명을 함께 남겨 활성화 범위를 정한다.
